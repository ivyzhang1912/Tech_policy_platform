# 科政鸣：科技政策摘要与个性化推送小程序

这是我本科时带队做的一个项目，2023 年参加中国大学生计算机设计大赛，拿了江苏省二等奖。

做这个项目的起因很简单：科技政策一篇动辄几千字，散落在各级政府网站和公众号里，真正需要它的企业和科研人员很难及时找到、也没时间细读。所以我们想做一个小程序，把政策先压缩成摘要，再根据每个人的浏览习惯，把可能相关的政策推给他。

## 整体流程

1. **政策文本清洗**：爬下来的政策正文混着很多网页噪音，比如“扫一扫在手机打开当前页”“阅读原文”、公众号的订阅提示，先按规则把这些切掉。
2. **摘要生成**：把清洗后的正文按句号切分、去掉条款序号，整理成摘要模型的输入格式，模型生成摘要后再汇总回表格。
3. **关键词提取**：用逆向最大匹配分词（自建词表加停用词表），再算 TF-IDF，给每条政策留 10 个权重最高的关键词。
4. **个性化推送**：用户每看一条政策，就把这条政策的关键词和权重累加进他的偏好画像（只保留前 10 个关键词）。推送时用画像给所有政策打分，取前 20 条。
5. **小程序前端**：首页热门政策、按类型和地区筛选的政策库、搜索、收藏、浏览记录和“为你推送”页面。

## 仓库结构

```
1_数据处理/
    1_清洗政策文本.py
    2_分句处理.py
    3_去除序号.py
    4_摘要结果汇总.py
    5_TF-IDF关键词提取.py
2_后端服务_Flask/
    app.py              登录、政策查询、收藏、浏览记录和推送接口（Flask + MySQL）
    requirements.txt
3_微信小程序/           小程序前端代码
4_演示视频/             小程序的操作演示
```

## 运行说明

- 后端需要一个名为 `tech_policy` 的 MySQL 数据库，数据库密码和小程序的 AppSecret 通过环境变量 `DB_PASSWORD`、`WX_APPSECRET` 传入。
- 小程序用到了 `tdesign-miniprogram` 和 `dayjs` 两个组件库，需要先在 `3_微信小程序` 目录下 `npm install`，再在微信开发者工具里构建 npm。
- 前端里的接口地址是当时局域网里的测试地址，自己运行时要改成后端实际的地址。
- 数据处理脚本里的文件路径是我当时本机的路径，需要按自己的目录调整。

## 没有放上来的部分

- **政策数据**：3,000 多条政策原文、清洗结果、摘要和数据库导出文件都没有上传。
- **摘要模型**：模型训练的代码不在这个仓库里，这里只保留了模型输入和输出两端的处理脚本。

## 回头看

这是我第一次把一个模型真正做成别人能用的东西。写后端和小程序的时候我才意识到，模型效果只是一部分，数据干不干净、推荐结果能不能说清楚为什么推给你，同样决定了这个工具好不好用。
